## Purpose

Demonstrate that Cali Core's saved operational context survives a full host restart, can be retrieved remotely, and can be reconstructed by the running Cali interface using `/resume`.

## Test platform

- **Host:** Dell OptiPlex 7010 (Linux Mint XFCE; `aesir-OptiPlex-01`)
- **Processor / memory:** Intel Core i3-3220 / 8 GB DDR3
- **Storage:** 128 GB SSD
- **AI system:** Cali Core v0.8, with persistent checkpoint and research-journal retrieval
- **Client:** Windows PowerShell over SSH on local network
- **Host address during test:** `192.168.1.22`
- **GPU:** No dedicated GPU required for this test; GPU power supply remains pending

## Procedure and observed evidence

1. **Restart:** The OptiPlex was rebooted. Subsequent remote SSH access succeeded.
2. **Checkpoint retrieval:** From Windows PowerShell, this command succeeded:

   ```powershell
   ssh phil@192.168.1.22 "cat ~/.local/share/cali_core/checkpoint.json"
   ```

3. **Checkpoint content:** The persisted JSON was readable and included:
   - `version`: `1`
   - `timestamp`: `2026-11-01T18:35:57.676669+00:00`
   - `active_project`: `Cali Core Development`
   - `last_completed`: `Cali Core v0.8 installed and operational checkpoint retrieval verified`
   - `current_task`: `Verify operational memory recovery after system restart`
   - `next_task`: `Complete full OptiPlex reboot and recovery test`
   - `pending_hardware`: `GPU power supply`
   - `pending_tests`: `Full system reboot recovery`
   - `last_interaction_utc`: `2026-11-01T21:08:40.444966+00:00`
   - `last_action`: `/resume`
   - `interaction_count`: `10`
4. **Manual context recovery:** In the Cali interface, Phil issued `/resume`. Cali reported the project, prior completion, current and next tasks, pending hardware, and pending test from the checkpoint.
5. **Research journal access:** The same response reported **1 journal entry**, showing entry **#3 [note] USER NOTE (unverified)** with a note stating that persistent-memory inspection, SQLite database integrity check, and backups had previously been completed. Cali explicitly cautioned: **“Literal source evidence is not proof of runtime hardware behavior.”**

## Engineering conclusion

**Cali Core v0.8 demonstrated durable operational-state storage and successful *manual* recovery after a full host restart.** The checkpoint and at least one research-journal note remained available and were used to reconstruct the working context. This is a validated step toward continuity across restarts, but it is **not** evidence of autonomous startup, uninterrupted computation, or portability across hardware.

## Follow-on work — proposed v0.9

1. Update checkpoint and project journal to mark the full reboot/manual recovery test **complete**; remove it from pending tests.
2. Add automatic checkpoint writes at meaningful task transitions, with atomic writes and validation.
3. Detect the saved checkpoint at program startup and optionally offer or perform an automatic context restore.
4. Log startup, shutdown, recovery outcome, and checkpoint version for traceability.
5. Test clean shutdown, abrupt interruption, and corrupted-checkpoint recovery separately.
